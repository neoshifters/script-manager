# 脚本管理（script-manager）

一个面向短视频 / 口播团队的「镜头脚本 + 素材剪辑」工具。服务端是一个 Go 单文件程序，前端是原生 HTML/CSS/JS 并打包进二进制；同事用浏览器打开同一个地址即可协作编辑，不需要安装客户端、Node 运行时或数据库。

- 单文件运行：Windows 一个 exe，Linux 一个可执行文件，或一个 Docker 镜像
- 零第三方依赖：只用 Go 标准库，前端无构建步骤
- 数据即文件：产品 / 脚本 / 文案都是普通目录和 JSON，直接备份、迁移、给别的程序读取

## 核心功能

- **镜头表格**：按产品 → 脚本组织，每个脚本是一张镜头表（镜头序号 / 镜头内容 / 口播 / 文案 / 视频片段），底部加号增行，随时增删。
- **视频片段拖入**：把视频从系统里直接拖进镜头的「视频片段」格，服务端接收后按镜头序号落盘为 `1.mp4`、`2.mp4`…，刷新后仍在、可直接播放。
- **智能裁切**：调用 ffmpeg 的 `scdet` 按画面变化自动找切点，切点进入时间轴，可调灵敏度（切点少 / 标准 / 切点密）。
- **打点与时间轴**：右侧剪辑面板支持拖时间轴、按 `S` 打点、按 `A` / `D` 按真实帧率逐帧移动，原片、切点、帧率、播放位置随文案一起保存。
- **多人实时协作**：同一份脚本可多人同时编辑，改动按「镜头 × 字段」粒度合并，不会后保存覆盖先保存；能看到同事正在编辑的单元格（彩色边框 + 名字）；断线重连自动补发，不丢改动、不产生重复行。
- **双通道同步**：优先 WebSocket，被代理拦截时自动降级为 HTTP 轮询，网络恢复后切回。
- **剪映草稿导出（可选）**：把镜头表导出成剪映草稿目录，素材一并复制；也支持导出 CSV + 时间码文案作为兜底。
- **预览**：点击视频卡片播放，空格播放 / 暂停，`Esc` 退出。

## 快速开始

### 方式一：本地运行（源码）

需要 Go 1.23 或更高版本。

```bash
git clone https://github.com/neoshifters/script-manager.git
cd script-manager
go build -trimpath -ldflags="-s -w" -o script-manager .
./script-manager
```

Windows 上构建出的是 `script-manager.exe`，双击即可。默认行为：

- 监听 `:8686`，启动后自动打开浏览器（Windows / macOS）
- 在程序同级目录创建 `脚本管理` 作为数据目录
- 局域网内其他人访问 `http://<这台机器的IP>:8686` 即可一起用

命令行参数与环境变量：

| 参数 | 环境变量 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `-addr` | `SM_ADDR` | `:8686` | 监听地址，例如 `:9000` |
| `-data` | `SM_DATA` | 程序旁边的 `脚本管理` | 数据目录，必须是本机可写路径 |
| `-open` | `SM_NO_OPEN` | 自动打开 | `-open=false` 或设置 `SM_NO_OPEN=1` 可关闭 |
| — | `SM_FFMPEG` / `SM_FFPROBE` | 自动查找 | 手动指定 ffmpeg / ffprobe 路径 |
| — | `SM_DRAFT_ROOT` / `SM_DRAFT_NAS` / `SM_DRAFT_WIN` | 空 | 剪映草稿导出用，见部署文档 |

### 方式二：Docker

仓库自带 `Dockerfile` 与 `docker-compose.yml`，镜像构建时会把 ffmpeg / ffprobe 一起装进去，智能裁切开箱可用。

```bash
# 可选：在同目录建 .env，指定宿主机数据目录
# SCRIPT_DATA_DIR=/你的绝对路径/script-manager-data
# JIANYING_DRAFT_DIR=/你的绝对路径/剪映草稿

docker compose up -d --build
```

- 默认把当前目录下的 `./data` 挂到容器 `/data`，`./drafts` 挂到 `/drafts`
- 访问 `http://<宿主机IP>:8686`，右上角应显示「ffmpeg 就绪」
- 容器重启策略为 `restart: always`，删除容器不会丢数据（数据在挂载目录里）

### 方式三：飞牛 NAS 部署要点

飞牛（fnOS）可以用 Docker Compose 直接部署，几个容易踩的点：

1. `volumes` 必须写**宿主机绝对路径**，并整体加引号，例如 `- "/vol1/1000/script-manager/data:/data"`；写成相对路径会在错误的位置建目录。
2. `SM_DATA=/data` 和 `/data` 挂载**两个都要有**：只写挂载不写 `SM_DATA`，数据会落在容器内部，重建即丢。
3. 数据目录和草稿目录的权限建议 `1000:1000` / `0775`，否则宿主机通过 SMB 看可能是空目录。
4. 本工具**没有登录与权限控制**，只适合部署在可信内网，不要直接暴露到公网。

完整的飞牛 / Docker / Windows 部署步骤、权限修复、故障排查见 [部署说明.md](部署说明.md)。

## 数据目录结构

```
脚本管理/                      # 数据根目录（-data / SM_DATA）
├── 产品A/
│   ├── 脚本一/
│   │   ├── 文案.json          # 镜头表格 + 剪辑面板状态（可直接备份 / 读取）
│   │   ├── 协同.json          # 协作权威状态，请勿手工编辑
│   │   ├── 1.mp4              # 镜头序号 1 的视频片段
│   │   └── 2.mp4
│   └── 脚本二/
│       └── 文案.json
├── _剪辑素材/                  # 剪辑面板导入的原片（临时区，不会自动清理）
├── bin/                       # 可选：手动放置的 ffmpeg / ffprobe
└── 设置.json                   # 页面里手动指定的路径（存在时才生成）
```

- `文案.json` 是物化的普通 JSON，每次合并后约 500ms 写入，可直接备份或用其他程序读取。
- `协同.json` 保存字段级寄存器与文档世代，服务端重启后从这里恢复；不要手工修改或删除（删除后会退化为按 `文案.json` 重建）。
- 视频切片统一为 H.264 + AAC 的 MP4，保证各浏览器都能播放。

## ffmpeg 依赖

智能裁切、切片、帧率读取都依赖 ffmpeg / ffprobe：

- **Docker**：镜像已内置 `/usr/bin/ffmpeg`、`/usr/bin/ffprobe`，无需额外安装。
- **Windows**：`winget install Gyan.FFmpeg`，或把免安装版的 `bin` 目录放到程序同级目录；也可以在页面右上角「ffmpeg」设置里手动指定。
- **Linux**：用发行版的包管理器安装，例如 `apt install ffmpeg`。

查找顺序：页面设置 → `SM_FFMPEG` / `SM_FFPROBE` → 程序同级目录及其 `bin/` → 数据目录及其 `bin/` → 系统 `PATH` → 常见安装位置。找不到时页面会明确提示，不会静默失败。

## 已知限制

- **没有认证和权限**：任何能访问端口的人都能读写全部数据，请仅用于可信内网。
- **单进程内存房间**：协作状态在服务进程内存里维护，不支持多实例同时写同一个数据目录。
- **同一脚本建议 ≤ 8 人**：超过不会被拒绝，但在线光标与广播开销会随人数线性增长。
- **合并粒度是单元格**：同一格被两人同时修改时保留最后写入的值（混合逻辑时钟判定），不是字符级协同。
- **视频兼容性**：H.265 的 MOV 在部分浏览器无法预览；切片会重编码为 H.264/AAC 以兼容浏览器。
- **剪映导出依赖剪映版本**：剪映没有公开导入接口，草稿格式随版本变化；不识别时请用 CSV + 时间码文案兜底。
- **移动端未适配**：界面按桌面浏览器设计。
- 仓库不包含预编译二进制，请自行构建或使用 Docker。
